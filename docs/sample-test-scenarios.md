# Sample 리그 일일 테스트 시나리오 (운영 플로우 기준)

이 문서는 `sample` 리그를 이용해 매일 동일한 기준으로 회귀 테스트하기 위한 체크리스트입니다.

---

## 0) 테스트 전 준비

- [ ] 샘플 데이터 리셋 완료 (수동 버튼 기준)
- [ ] 테스트 계정 준비
  - 운영자 1
  - 매니저 2~3 (팀별)
  - 일반 계정 1~2
- [ ] 오늘 테스트 로그 기록 시작 (날짜/브랜치/커밋)

권장 기록 템플릿:
- 날짜:
- 테스트 대상 커밋:
- 성공/실패:
- 이슈 링크:

---

## 1) 운영자: 경기그룹 일정 등록

- [ ] 경기그룹 생성 (날짜/장소/타이틀)
- [ ] 경기 추가 (A팀/B팀/경기구간수)
- [ ] 경기구간수 수정 시 period 패널이 정상 반영되는지 확인
- [ ] 경기 목록/정렬/표시 이상 없는지 확인

중요 확인:
- period가 2 이상일 때 선발 입력 UI가 구간별로 표시되는지
- 팀명 수정 후 매니저 화면/경기 화면 연동이 깨지지 않는지

---

## 2) 각 매니저: 경기그룹 엔트리 등록

- [ ] 각 팀 매니저가 자기 팀 엔트리 체크 후 제출
- [ ] 용병 선택(또는 해제) 후 제출
- [ ] 제출 중 로딩(`제출중...`) 표시 확인

중요 확인:
- 이미 선발 제출된 상태에서 엔트리 변경 시 경고(confirm) 노출
- confirm 진행 시 선발명단 정리(엔트리 제외 선수 제거) 동작
- confirm 취소 시 데이터 미변경

---

## 3) 운영자: 경기그룹 엔트리 확정

- [ ] 엔트리 확정 버튼 동작
- [ ] 확정/해제 상태 표시 확인
- [ ] 확정 후에도 조회/운영 플로우가 정상인지 확인

---

## 4) 일반 계정: 자기 팀 외 경기 시작/진행 + 이벤트 등록

- [ ] 자기 팀 외 경기만 편집 가능한지 확인
- [ ] period 시작/종료/재개 버튼 상태 확인
- [ ] 골 추가(모달) 등록
  - [ ] 기본 minute 값 검증 (전반/하프타임/후반)
  - [ ] 득점자 선택 시 어시스트에서 동일 선수 제외
- [ ] 교체 추가(모달) 등록
  - [ ] OUT=출전중, IN=벤치 제약
  - [ ] 예약 교체(시작 전/하프타임) 동작
  - [ ] undo 동작

중요 확인:
- LiveScoreboard 이벤트 정렬
  - 같은 period 내 START/골/교체 순서가 자연스러운지
  - period 경계에서 이벤트 섞임 없는지
- START 마커 클릭 시 해당 period 선발 명단 표시

---

## 5) 경기 후: 참여 계정 상대 평점 등록

- [ ] 참여한 계정으로 상대 선수 평점 입력
- [ ] 자기 팀 선수 평점 제한 동작 확인
- [ ] 동일 계정 재입력 시 갱신 동작 확인

---

## 6) 통계 업데이트 확인

- [ ] 순위/득점/도움/평점 통계 반영
- [ ] 동률 순위 표기(competition ranking) 확인
- [ ] Top 5 / 펼치기 동작 확인

---

## 7) 반드시 추가로 봐야 할 항목 (누락 방지)

아래는 운영 흐름 외에 자주 깨지는 핵심 회귀 포인트입니다.

### A. 권한/범위
- [ ] 매니저는 자기 팀만 수정 가능
- [ ] 일반 계정은 자기 팀 경기 편집 불가
- [ ] 운영자 권한 우선 동작

### B. 데이터 무결성
- [ ] 엔트리 변경 ↔ 선발/교체 데이터 정합성 유지
- [ ] 삭제/수정 후 타임라인 고아 데이터 없는지
- [ ] match_period_id 기반 조회에서 null/미매핑 케이스 없는지

### C. 모바일 UI
- [ ] 390px 전후 화면에서 폼 깨짐/버튼 겹침 없는지
- [ ] 스크롤 구간(선수 체크리스트) 조작성

### D. 성능/캐시
- [ ] 경기 진행 중 점수판 새로고침/자동 갱신 일관성
- [ ] 캐시 정책 변경 후 페이지 stale 문제 없는지

---

## 8) 실패 시 기록 규칙

이슈 등록 시 최소 포함:
- 재현 절차 (1~2~3)
- 기대 결과 / 실제 결과
- 계정 역할(운영자/매니저/일반)
- 경기/그룹 ID
- 스크린샷 1장 + 콘솔/서버 로그(가능 시)

---

## 권장 실행 주기

- 일 1회(배포 전)
- 주요 구조 변경(PR 대형) 직후 추가 1회

테스트 시간이 짧으면 1~4 단계까지를 "핵심 스모크"로 우선 실행하고,
5~7 단계는 격일 또는 주요 변경 때 전체 실행합니다.
